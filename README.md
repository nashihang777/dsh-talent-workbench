> **DeepSeek Harness 插件**：把简历筛选变成可解释、可调权重的本地流程——左边栏一个图标打开整页工作台，19 个独立考察维度、13 个岗位模板、逐维推导、批量导入（智能体识别字段）与匿名交换账本。

候选人信息只写本机 JSON 库；文字与 OCR 全部本地完成，仅字段识别会把你提取出的**纯文本**发给你自己配置的模型，可一键关闭。

## 安装

```bash
# 从 npm 安装（推荐）
dsh plugin install @nashihang777/dsh-talent-workbench

# 或直接用本仓库源码开发
git clone https://github.com/nashihang777/dsh-talent-workbench.git
```

安装后刷新页面，左侧导航栏会出现「人才匹配」图标。发布与版本号约定见 [RELEASING.md](RELEASING.md)。

## 它解决什么

常见的岗位筛选靠一张固定维度的评分表：每个维度有等级、命中数、A/B 两套规则。问题也很清楚：**维度权重没有被显式管理**，跨学科、补齐落地短板这类维度会把结果系统性推向机械/控制专业；换一个岗位，维度组合也应该换。

这个插件把流程拆成三件事：

1. **岗位模板**：从维度技能库里选维度，给每个维度设相对权重、可选门槛、推荐/备选阈值。权重是相对值，系统自动归一化。
2. **维度技能**：19 个独立、可版本化的考察规范。前 8 个面向研究型岗位（技术栈匹配度、跨学科、学术水平预估、补齐落地短板、补齐理论深度、长期学术潜力、科研经历深度、科研专注度）；后 11 个面向互联网/制造/医疗/金融等通用岗位族（工程质量与可靠性、系统设计与架构、数据与实验能力、算法建模与调优、业务理解与产品思维、领域知识与行业经验、协作推进与沟通、结果导向与交付节奏、学习迁移速度、现场实施与客户界面、合规与风险意识）。每个规范都写清考察目标、方法、证据清单、分级标准、反偏差、面试追问和输出格式；同时注册为 DSH skill，智能体可以加载。
3. **可解释推导**：候选人 × 模板的每一维都展示「证据 → 等级 → 分值 × 权重 → 贡献」，并给出旧口径（命中数）位次、门槛未过项、专业集中度和权重扰动下的位次变化。

## 岗位族与模板（参考公开招聘信息）

模板参考公开招聘的职位名称与任职要求（只提炼共性考察点，不复制任何职位文案、公司名或个人信息）：

| 模板 | 参考职位类型 | 主要维度 |
|---|---|---|
| AI + 稀土研究岗（校准版 / 旧口径对照） | 研究型团队招聘 | 技术栈、学术水平、理论深度、科研经历 |
| AI 算法工程师（语音/视觉/NLP） | 语音算法专家、视觉/NLP 算法工程师 | 建模调优、工程质量、数据实验 |
| 后端开发工程师（Node/Java/Go） | Node.js 开发、后端开发 | 工程质量、系统设计、交付节奏 |
| 数据工程师 / 数据分析师 | 数据开发、数据平台 | 数据实验、工程质量、建模 |
| 数据分析师（业务分析） | 数据分析师、业务分析 | 数据实验、产品思维、交付 |
| 量化研究员 | 量化研究员、期权量化 | 建模调优、数据实验、合规风控 |
| B 端产品经理（工业/能源软件） | 智慧电厂产品经理、产品架构师 | 产品思维、领域知识、现场实施 |
| 实施 / 运维项目经理 | 应用系统运维项目经理、实施顾问 | 现场实施、协作、交付节奏 |
| 医疗器械 / 检验医学岗 | 检验医学专员、医疗器械研发/质量 | 领域知识、合规（硬门槛） |
| 智能制造 / 生产技术支持 | 生产技术支持、QA 现场、机械产品规划 | 现场实施、领域知识、工程质量 |
| 内控合规 / 风控岗 | 内控合规、风控 | 合规（硬门槛）、领域知识、协作 |
| 大客户销售 / 商务 BD | 商务营业、媒介商务 BD、解决方案销售 | 交付结果、客户界面、协作 |

**行业关键词（focus）**：每个行业模板可声明目标行业关键词（如「医疗器械」「量化金融」）。`领域知识与行业经验` 这一维度会对齐该行业：简历里没有任何该行业关键词时，该维度分值上限压到 0.4，并在推导里标注「行业不匹配」。这样同一份「泛领域」简历不会因为通用领域分高就挤进不相关行业的推荐位。关键词可在模板编辑器里改，留空则不校验。

**推荐线的含义**：不同岗位族的维度组合不同，能达到的总分也不同（例如医疗器械岗有硬门槛、维度更尖，理论上限低于后端岗）。模板里的推荐/备选线是**相对该岗位族**设定的，换模板后请按实际候选池分布复核，不要把一个模板的阈值套到另一个模板上。

## 新增候选人：手动录入与简历文件导入

两种方式并存，入口都在面板顶部与「筛选推导」工具栏：

1. **手动维护**（`新增候选人`）：逐字段填写，结构化证据（论文、项目、工程落地、理论方法、职务）可折叠分组维护，保存后立即做规则初筛。
2. **简历文件导入**（`批量导入简历`）：
   - 选择**多个文件**或**整个文件夹**（浏览器文件夹选择，含子目录），也可以填一个本机绝对路径交给主机侧读取（智能体同样可用）。
   - 支持格式：`.pdf`、`.doc`、`.docx`、`.rtf`、`.txt`、`.md`，以及 `.png/.jpg/.jpeg/.webp/.bmp/.tif/.tiff`。
   - 解析方式：DOCX 直接读 OOXML；DOC 读 Word 97-2003 复合文档的片段表；PDF 先取文字层，文字层太薄就逐页栅格化后 OCR；图片直接 OCR。
   - 导入前逐份给出**可编辑的建议字段**（别名/姓名、专业、学历、院校、方向）与**提取文本预览**；OCR 结果会标「需核对」并保留页图路径，可用 `read_image` 复核。
   - 同一候选人的多页扫描件会**按文件名自动合并**：`示例丙.jpg`、`示例丙（第一页）.jpg`、`示例丙（第二页）.jpg` 这类命名会归为一条记录，页序按「第N页」或尾部数字排序。
   - 内容相同的简历会标「疑似重复」（同一批内和与本地库比对都算），提交时自动跳过，不会重复入库。
   - 提交后才写入本地数据库，扫描期间的临时文件与页图会在提交或放弃后删除。

### 解析在后台运行（v1.6.0 起）

选完文件或文件夹后，解析任务在主机侧后台执行，前端只负责显示进度：

- 接口 `resumes.startScan` **立即返回**一个 `jobId`，不阻塞请求；前端每 0.9 秒轮询 `resumes.job`；
- 进度分两段：`正在解析文本（3/7 份）` → `智能体正在识别字段（4/7 份）`，页面上有进度条与已提取文件列表；
- **关闭导入窗口不会中断**：任务属于页面而不是对话框，窗口关掉后页面顶部仍显示进度条，点「查看进度 / 核对结果」可以随时回到列表；
- 切换标签页、返回对话页同理，任务继续；
- 刷新页面也能恢复：前端加载时调用 `resumes.jobs`，自动接上仍在跑的任务，或恢复最近一次已完成但未导入的结果；
- 可以 `取消任务`（取消后临时文件立即清理），也可以 `重新选择`（丢弃本次结果）。

结果保存在主机内存的任务表里，最多保留 6 个已完成任务；关闭任务或提交导入后临时文件才会删除。

### 字段由智能体识别（v1.5.0 起）

「批量导入简历」选完文件或文件夹后，**文字提取仍在本机**（DOCX/DOC、PDF 文字层、扫描件 OCR），
但**姓名、专业、学历、院校、方向以及论文/项目/工程/理论/职务/奖项等结构化字段，交给智能体读文本后给出**，
不再依赖正则。原因很直接：正则无法区分「研究领域里提到材料」与「材料专业博士」，
也分不清「教育经历」是栏目标题还是人名。

- 用哪条模型：默认沿用你在 DSH 里选的默认模型（可用 `import.agentProvider` / `import.agentModel` 指定）；
- 分批：默认一次 3 份（`import.agentBatch`），单份最多读 9000 字（`import.agentMaxCharsPerResume`），单次调用 90 秒超时；
- 返回后仍过一道白名单归一化：学历只接受「博士/硕士/本科」，作者位次、项目角色等枚举非法值会被丢弃或降级，
  模型没有依据的字段宁可留空；
- 每行都有 `智能体解析` / `规则解析` 徽标，摘要栏显示 `智能体解析 N/M`；
- **失败即回退**：模型不可用、超时或返回无法解析时，自动退回本地正则，行上标注「智能体解析失败，已退回本地规则」并给出原因；
- **关闭方式**：`import.useAgent: false`，完全走本地规则。

> 隐私边界：这是导入流程里唯一离开本机的环节——只把**已提取的纯文本**发往你自己配置的模型，
> 不上传文件、不上传图片、不发往任何第三方服务。关掉 `useAgent` 即完全不联网。

### 本地规则兜底（模型不可用时）

模型拿不到结果时用规则兜底，规则也按「最高学历学位」取值。

**专业以「最后学历学位」为准。** 先解析教育经历里每一条学位记录，取最高学位那一条的专业；同一条里还会剔除日期、学校、导师与学位词，只留专业：

```
        时间    学历        毕业学校              专业            导师
2018.09-2022.06 博士   示例市，示例大学        软件工程        示例教授   → 软件工程
2015.09-2018.06 硕士   示例市，示例大学      计算机科学与技术    示例教授
```

判定顺序：

1. **最高学位的教育记录**（两种写法都认）：
   - 带日期或学校的行：`2018.09-2022.06 博士 … 软件工程 … 示例教授`；
   - 抬头式：`材料科学与工程专业｜工学博士`。
2. 显式字段：`专业：…`、`学科：…`；
3. 文件名：`401_数学_示例甲.pdf` 这类招聘方自己整理的命名；
4. 最后才看开头 400 字的抬头。

两条防误判规则：

- **带标签的说明行不算教育记录**：以 `研究领域 / 研究方向 / 参研项目 / 求职意向 / 技能 / 论文 成绩…` 开头的行会被跳过。这一条正是此前把示例乙判成「人工智能」的原因——他的 `研究领域：…生成式人工智能` 抢在了教育表格前面。
- **弱词只在可信语境生效**：`材料 / 化学 / 物理 / 数学 / 力学` 这类同时也是普通词的短名，只认教育记录、显式字段与文件名，正文里的零散提及不采纳；`机器学习 / 强化学习` 里的「化学」也会被屏蔽。

**院校**取最高学位那条记录的学校，并优先取其中的大学而非其下属学院（`示例大学 材料学院` → 示例大学）；`示例市，示例大学` 这种带城市前缀的写法也能正确切出校名。

**学历**同样以最高教育记录为准（`学士 → 本科`）。

**多人文件识别**：如果一个文件其实是名单、评审记录或表格（3 条以上编号条目，或 3 处以上「姓名：」，或 2 处姓名标签 + 4 处以上学位词），导入时会标「疑似多人文件」并**默认不勾选**，提交时也会跳过。这类文件不适合当单份简历入库。

**修正历史记录**：「数据备份」页有两个按钮：

- `用智能体复核`（推荐）：把已存的简历文本交给模型重读，修正姓名/专业/学历/院校/方向，并在结构化证据为空时补录论文、项目、工程经历；先预览再应用，应用后重跑规则初筛并记审计。多人文件会被跳过。智能体侧是 `talent_screening action=agent_refresh_fields`（省略 `apply` 为预览）。
- `核对导入字段`（不联网）：只用本地规则重新推算，不消耗模型额度。对应 `action=refresh_import_fields`。

名字只在规则解析的记录上会被模型覆盖（规则常把 `教育经历`、`应试者` 当人名）；已经由模型解析过的记录不会被再次改名，避免覆盖人工修正。

已导入候选人的 `profileText` 是提取出的简历全文，来源文件名与解析引擎记录在 `sourceFile` / `extraction` 里；结构化证据（论文/项目/工程/理论/职务/奖项）由智能体在导入时一并抽取；模型没给出时为空，可在候选人资料里补录后重跑评估。

OCR 说明：使用 Windows 自带的 `Windows.Media.Ocr`（中文 `zh-Hans-CN`、英文 `en-US`）。实测中文简历识别质量可用，但会把空格插进汉字之间、偶发形近字错误——插件已做空格清理与常见错字修正，仍**必须人工核对**关键字段。PDF 栅格化依赖 poppler 的 `pdftoppm` / `pdftotext`（TeX Live、MiKTeX 或独立 poppler 均会带），找不到时扫描版 PDF 无法 OCR，会在界面里明确报错。没有装 Word/LibreOffice 也能解析 DOC/DOCX。

## 打开方式

入口在**左侧全局导航栏**（和「插件」「定时任务」并列）：

- 点击左栏的 **人才匹配** 图标（一个「列表 + 侧栏」形状的图标），主区域会切换为工作台整页；
- 它不再是对话输入框旁的按钮，也不占用右侧栏；返回对话点左栏的对话图标即可；
- 页面打开后先看到「总览」，说明模板、草稿与推导的关系。

## 界面结构

整页布局，宽度跟随主区域（适合看 19 个维度、13 个模板与逐维推导）：

- **页头**：标题、本地/隐私徽标、当前模板选择、`批量导入简历`（浅色强调）与 `新增候选人`（实心主色）；
- **标签页**：总览 / 筛选推导 / 岗位模板 / 维度技能 / 匿名交换 / 数据备份，带条目计数；
- **筛选推导**：左列候选人、中列逐维证据、右列判定分数与判定线（宽屏三列，窄屏自动堆叠并优先显示分数卡）；
- **按钮层级**统一为四档：实心主色＝当前页面主操作，浅色强调＝次要但常用，描边＝普通操作，幽灵/红色＝低权重或危险操作。

## 草稿与当前模板

- 在「岗位模板」里调权重会立即在「筛选推导」中按草稿计算并显示 `未保存草稿` 标记；切模板前会提示是否丢弃。
- 「保存为新版本」之后草稿才会写入本地数据库；新建模板保存后自动成为当前模板。
- 「设为当前模板」决定筛选推导使用哪个已保存模板；模板列表里会标出当前模板。

## 本地数据与隐私

- 数据目录：`$DSH_PROFILE_DIR/talent-workbench/`（默认 `~/.dsh/profiles/<profile>/talent-workbench/`），`db.json` + `db.backup.json` + `instance.json`。
- 人才姓名、简历原文、联系方式、证据、评估与模板/技能版本都只写入这个本地目录。面板只调用本机 DSH 服务的同源接口（`/dsh-talent/api`，仅接受回环地址），不向外部网络发送数据。
- **匿名交换包**只允许：维度均值、等级占比、归一化权重、样本量分级、岗位族、匿名实例标识、完整性哈希。导入时执行字段白名单、隐私特征扫描（邮箱/手机号/身份证/URL/长数字串/超长自由文本）与 SHA-256 完整性校验。
- 候选人数少于 5 人时导出会提示：均值接近个人画像，建议累计样本后再交换。
- 本地账本是 SHA-256 哈希链，用于防篡改与回溯；它是协同进化机制的**本地原型**，没有连接公链，也不会自动联网。交换通过手动导出/导入 `.json` 完成。
- 完整备份包含个人信息，只应保存在本机；界面会明确提示。

## 版本与回溯

- 模板每次保存生成新版本；技能每次编辑生成新版本；都可回溯（回溯本身也生成新版本，不覆盖历史）。
- 版本历史会显示每一版的维度权重，便于回溯前先看清差异。
- 每次「生成筛选快照」记录当时的模板版本、技能版本、权重、逐人结果与专业分布。
- 审计记录保留最近 200 条本地操作。

## 智能体工具

`talent_screening` 工具提供：

`overview`、`list_candidates`、`evaluate`、`import_candidate`、`scan_resumes`、`import_resumes`、`set_assessment`、`preview_pack`、`export_pack`、`import_pack`、`verify_chain`。

示例流程：

```
talent_screening action=scan_resumes path="D:\\人才招聘\\第三批次" recursive=true
```

## 示例数据（只在前端，不落库）

22 位**虚构**候选人（14 位研究型 + 8 位互联网/制造/医疗/金融岗位族）随插件打包在 `client.js` 里，**只用于首次打开时的界面预览**：

- 它们**不写入数据库**。`buildSeedDb()` 的候选人表为空，升级时也会把旧版本存过的示例行清掉（审计里记一条 `data.purgeSamples`）。
- 只要本地有任意一位真实候选人（导入或手动新增），示例立即隐藏；清空全部候选人后示例会重新出现，便于再次演示。
- 示例候选人在界面上是**只读**的：不能编辑、不能改判级、不能生成快照或报告；工具栏顶部有 `示例预览` 标记和说明条。
- 示例数据的等级是在打包时用同一套规则引擎预算好并内嵌的，`dev/industry-smoke.mjs` 会比对内嵌值与引擎当前输出，防止两者漂移。

13 个模板与 19 个维度技能属于真实内容，会写入数据库并保留版本历史。

两个研究型模板刻意形成对照：旧口径把「跨学科」「补齐落地短板」调高，推荐名单会被机械/控制背景占据，偏差诊断会点名；校准版降低这两项、提高技术栈与学术水平，推荐名单更分散。这是给招聘方练习"调权重 → 看诊断 → 再调"的示例，不是唯一正确答案。

11 个行业模板各自都能在自己的虚构"对口候选人"上排第一（`dev/industry-smoke.mjs` 会断言这一点），用来演示同一批人在不同岗位模板下排序完全不同。

## 已知限制

- 交换是本地哈希链 + 手动文件交换，不是公链，也没有共识、激励或女巫防护；跨机构协作需要额外的信任与身份层。
- 示例候选人不入库，因此 `talent_screening` 工具（面向智能体）永远看不到它们；智能体只处理真实候选人。
- 规则初筛是确定性的启发式，不替代面试与人工判断；界面明确标注「规则初筛 / 人工复核」。
- 维度技能的内容是领域规范，不是法律意见；招聘决策仍需遵守当地劳动法与反歧视要求。
- 面板依赖当前 Web profile 的 `webServer` 路由；在没有该服务的运行环境里，工具仍可用，但面板无法读取本地数据。
- 界面以中文为主，英文只覆盖主要导航与关键提示；技能正文是中文领域内容。
- 新增的 11 个维度是**关键词/结构启发式**初筛（例如「单元测试」「CI」「AB 实验」「实盘」命中即加分），只能给起点等级；界面会列命中的关键词，必须按技能里的追问人工核实。
- 行业模板的推荐线是相对该岗位族设定的；不同模板的总分不可直接横比，换模板后请复核阈值。
- 简历导入：OCR 有错字风险，必须人工核对；多页 TIFF 只识别第一页，扫描版 PDF 默认只 OCR 前 6 页（`import.maxOcrPages` 可调）；表格、双栏排版与公式容易识别错行；加密 PDF/DOC 会失败并给出原因。
- 多页合并依赖文件名：`（第N页）`、`_p2`、`-2` 这类后缀会被去掉后归并；如果同一页被命名成完全无关的文件名，就需要手动选中或分两次导入。
- 单批上限 40 份 / 40 MB（可在配置里调）；批量越大 OCR 越久，界面会显示已用时间，解析期间请保持窗口打开（关闭会在解析结束后自动清理临时文件）。
- 简历解析到结构化证据（论文位次、项目角色、工程落地）仍是规则启发式，只用于维度初筛；关键判断请按维度技能里的追问在面试中核实。

## 配置

`cordis.patch.yml` 中该插件行可覆盖：

```yaml
- id: talent-workbench
  name: '@nashihang777/dsh-talent-workbench'
  config:
    dataDir: ''                 # 留空 = $DSH_PROFILE_DIR/talent-workbench
    autoRegisterSkills: true
    allowRealNames: false       # true 才允许界面显示实名
    import:
      maxFiles: 40              # 单次扫描文件数上限
      maxBytes: 50331648        # 单次上传总字节上限（48 MB）
      maxOcrPages: 6            # 扫描版 PDF 最多 OCR 的页数
      ocrScaleTo: 2400          # 栅格化后的最长边像素（扫描件页面经常标称超大尺寸，按像素限长才快）
      ocrLanguage: 'zh-Hans-CN'
      poppler:
        pdftotextPath: ''       # 留空 = 自动在 PATH 与常见安装目录中查找
        pdftoppmPath: ''
```

## 开发

- `index.js`：Host 入口、本地 API、技能注册、`talent_screening` 工具。
- `lib/`：种子数据、评分引擎、本地存储、匿名交换、工作台服务。
- `lib/import/`：简历解析（`extract.js` 调度、`zip.js` 读 DOCX、`ole.js` 读 DOC、`pdf.js` 调 poppler、`ocr.js` + `windows-ocr.ps1` 调 Windows OCR）。
- `client.js`：右侧栏工作台面板（React，无第三方依赖）。
- `skills/`：8 份可移植的 `SKILL.md` 规范副本；运行时以本地数据库版本为准。
- `docs/`：插件详情页与配图。
- `dev/`：本地自检脚本（不随包发布）。`node dev/smoke.mjs` 验证服务与交换，`node dev/industry-smoke.mjs` 验证 11 个行业模板各自把"对口候选人"排第一、行业关键词上限生效、旧数据库升级时只补新增内容，`node dev/import-smoke.mjs` 现场生成 DOCX/TXT 夹具并验证解析与入库，`node dev/render-smoke.mjs` 用占位 React 渲染全部界面分支。
