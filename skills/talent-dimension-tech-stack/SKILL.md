# 技术栈匹配度

> 维度技能 `talent-dimension-tech-stack` · 版本 v1 · 本地存储 · 可回溯

## 考察目标

判断候选人的技能与「AI + 高纯稀土 / 湿法冶金」技术栈是直接命中、可迁移，还是只有工具级关联。

## 何时使用

岗位需要同时理解材料/冶金过程与数据/模型，或需要 LLM/Agent 工程能力时使用；技术栈是主权重维度，但不可只看专业名称。

## 判定方法

1. 先把岗位拆成三层锚点：对象层（稀土冶金、永磁、储氢、抛光、萃取、高纯金属等）、方法层（第一性原理、分子动力学、CFD、过程建模、时序模型、强化学习、RAG、Agent 等）、交付层（产线、装置、控制系统、软件平台、现场验证）。
2. 从简历中逐条抽取「问题 → 方法 → 结果」证据链；每条证据必须能回答做了什么、数据/对象是什么、规模多大、结果如何、本人负责哪一部分。
3. 把证据归入四类：同对象同方法（直接）、同方法换对象（可迁移）、同对象换方法（可迁移）、只有工具或课程（弱相关）。
4. 按分级标准判级；证据只来自课程、自学或团队成果时降一档，并写明缺失证据。
5. 给出置信度：结构化字段齐全且有一手项目证据为高；只有简历文字为中；只有关键词为低。

## 证据清单

- 项目：对象、数据量、模型/算法、上线或验证结果、个人负责模块。
- 论文/专利：方法是否本人实现，是否与岗位对象同源。
- 实习/工程：系统规模、部署环境、指标、故障处理。
- 技能：能说明在哪个项目里用过，而不是仅列名词。

## 分级标准

| 等级 | 分值 | 判定口径 |
|---|---|---|
| 高 | 1 | 直接命中岗位核心问题，且已有可验证的独立产出。 |
| 中上 | 0.8 | 核心一侧较强，另一侧可迁移，短期补齐成本低。 |
| 中 | 0.6 | 有可迁移的方法或平台能力，需要换体系验证。 |
| 中下 | 0.4 | 只有工具级或间接相关经验，独立支撑能力弱。 |
| 低 | 0.2 | 与岗位问题链没有可用接口。 |

## 反偏差与反幻觉

本维度最容易把「专业标签」当成匹配度。必须按问题链证据判级，并明确区分直接、可迁移、弱相关；机械、控制、计算机不会因为专业名称自动加分，材料/化学也不会自动高分。

## 面试追问

- 你解决的预测/控制/设计问题，具体输入输出是什么？数据从哪里来、多少条、怎么清洗？
- 如果把材料体系换成稀土，你的方法哪一步必须重做？哪一步可以直接复用？
- 你负责的模块上线后，用什么指标衡量有效？失败案例是什么？
- 请挑一个项目，说明从问题定义到结果验证你独立做了哪三件事。

## 输出格式

等级（高/中上/中/中下/低）、证据链、可迁移点、缺失证据、置信度。

## 校准建议

若岗位已有多名机械/控制背景成员，本维度权重不宜超过 25%；若团队缺的是领域知识，则优先看对象层证据而不是工具列表。

## 岗位锚点（示例）

- 稀土冶金
- 永磁/储氢/抛光
- 湿法萃取
- 高纯金属
- 过程建模
- 过程控制
- 材料预测
- LLM/Agent 工程

## 使用约束

本技能只服务于本地筛选与面试准备，不得把候选人姓名、联系方式、简历原文或任何可识别个人的信息写入交换包。判级必须引用证据；证据不足时降低置信度，不得编造。
