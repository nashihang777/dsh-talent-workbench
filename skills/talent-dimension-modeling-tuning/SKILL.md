# 算法建模与调优

> 维度技能 `talent-dimension-modeling-tuning` · 版本 v1 · 本地存储 · 可回溯

## 考察目标

考察把业务问题转成可优化目标、选对方法并持续迭代的能力：指标、基线、消融、误差分析与上线后的再训练。

## 何时使用

算法、机器学习、量化、信号处理与优化类岗位；用于区分「调用现成模型」与「能自研核心模块」。

## 判定方法

1. 先问问题定义：优化目标是什么、约束是什么、评价指标与业务指标如何对齐。
2. 看基线：有没有简单基线、提升幅度是否显著、是否做过消融与误差分析。
3. 看方法深度：能否解释所选方法的假设与失效边界，而不是只报模型名。
4. 看工程耦合：推理时延、显存/算力预算、数据闭环与再训练机制。
5. 量化/信号类岗位额外看：数学推导、数值稳定性、极端场景下的退化表现。

## 证据清单

- 任务定义、指标与基线对比。
- 消融实验、误差分析、失败案例。
- 关键指标数字（准确率/F1/AUC/MOS/唤醒率/回撤等）与测试条件。
- 上线后的迭代记录与再训练机制。

## 分级标准

| 等级 | 分值 | 判定口径 |
|---|---|---|
| 高 | 1 | 在真实生产/一线环境中独立做到，且有可验证结果。 |
| 中上 | 0.8 | 有完整实践与量化结果，复杂度或规模略低。 |
| 中 | 0.6 | 做过同类事情但以参与为主，或停留在非生产环境。 |
| 中下 | 0.4 | 有课程/实习级接触，缺少独立交付证据。 |
| 低 | 0.2 | 没有相关证据，或只有名词级了解。 |

## 反偏差与反幻觉

不要用模型规模或论文数量替代任务级证据；能自研核心模块并说清边界，比堆叠开源组件更有价值。

## 面试追问

- 你的任务指标是什么？简单基线是多少？你的提升来自哪个改动？
- 哪一类样本你的模型最容易错？你怎么发现并处理？
- 如果算力砍到十分之一，你会怎么改方案？

## 输出格式

等级、任务与指标、基线对比、消融与误差分析、成本约束、缺口。

## 校准建议

算法岗 20%—30%；数据/平台岗 10% 以内；量化岗可到 25%。
