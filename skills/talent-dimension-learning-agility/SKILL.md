# 学习迁移速度

> 维度技能 `talent-dimension-learning-agility` · 版本 v1 · 本地存储 · 可回溯

## 考察目标

考察进入陌生领域并快速产出的能力：学习路径、迁移证据与失败后的调整速度，而不是「学过很多语言」。

## 何时使用

跨行业/跨技术栈招聘、需要快速补位的岗位，以及判断长期成长性时使用。

## 判定方法

1. 找一次真实的领域切换：从零到能交付用了多久，怎么学的，第一个产出是什么。
2. 看迁移：能否把一个领域的方法论正确搬到另一个领域，并识别哪些假设失效。
3. 看学习方式：是否有结构（文档、源码、复现、请教专家），而不是只刷教程。
4. 看调整速度：遇到不懂的问题，多久能定位到「该问谁/该读什么」。
5. 避免把「学过多门语言/框架」当成学习能力，那是广度不是速度。

## 证据清单

- 领域切换的时间线与首个产出。
- 迁移案例：套用了什么方法、哪些不适用。
- 学习路径证据：复现、源码阅读、笔记、请教记录。
- 从错误中调整的具体例子。

## 分级标准

| 等级 | 分值 | 判定口径 |
|---|---|---|
| 高 | 1 | 在真实生产/一线环境中独立做到，且有可验证结果。 |
| 中上 | 0.8 | 有完整实践与量化结果，复杂度或规模略低。 |
| 中 | 0.6 | 做过同类事情但以参与为主，或停留在非生产环境。 |
| 中下 | 0.4 | 有课程/实习级接触，缺少独立交付证据。 |
| 低 | 0.2 | 没有相关证据，或只有名词级了解。 |

## 反偏差与反幻觉

不要用年龄、学历或「学习意愿」自评判断；只看可验证的迁移与调整速度。

## 面试追问

- 你最快一次从零学一门技术到能交付是什么时候？第一个产出是什么？
- 把一个领域的方法搬到另一个领域时，你踩过什么坑？
- 遇到完全不懂的问题，你的前 30 分钟怎么做？

## 输出格式

等级、切换时间线、迁移案例、学习路径、调整速度、缺口。

## 校准建议

跨行业招聘可提高到 15%；内部培养岗 10%—15%；急需即战力时降到 5%。

## 使用约束

本技能只服务于本地筛选与面试准备，不得把候选人姓名、联系方式、简历原文或任何可识别个人的信息写入交换包。判级必须引用证据；证据不足时降低置信度，不得编造。
