# 数据与实验能力

> 维度技能 `talent-dimension-data-experiment` · 版本 v1 · 本地存储 · 可回溯

## 考察目标

考察能否拿到干净数据、定义可信指标、用实验而非直觉判断效果：数据获取、口径、评估、A/B 与偏差识别。

## 何时使用

数据、算法、增长、产品与量化岗位；也用于判断「会用 SQL」是否真的等于数据能力。

## 判定方法

1. 按链路看：数据来源与获取 → 清洗与口径 → 标注/质检 → 指标定义 → 实验设计 → 结论与决策。
2. 追问指标口径：分母是什么、去重规则、异常值与缺失怎么处理、口径变更如何兼容历史。
3. 看实验：是否有对照组、样本量估算、显著性、多重比较、辛普森悖论等常见陷阱的处理。
4. 看数据质量：标注一致性（Kappa/一致性率）、抽样复核、脏数据比例。
5. 量化岗位额外看：样本外验证、幸存者偏差、过拟合与交易成本假设。

## 证据清单

- 数据集规模、来源、清洗与标注流程。
- 指标定义文档与口径变更记录。
- A/B 实验设计、样本量、结果与决策。
- 数据质量指标：一致性、缺失率、抽样复核结论。

## 分级标准

| 等级 | 分值 | 判定口径 |
|---|---|---|
| 高 | 1 | 在真实生产/一线环境中独立做到，且有可验证结果。 |
| 中上 | 0.8 | 有完整实践与量化结果，复杂度或规模略低。 |
| 中 | 0.6 | 做过同类事情但以参与为主，或停留在非生产环境。 |
| 中下 | 0.4 | 有课程/实习级接触，缺少独立交付证据。 |
| 低 | 0.2 | 没有相关证据，或只有名词级了解。 |

## 反偏差与反幻觉

不要用「会用 Pandas/SQL」当数据能力；也不要因为岗位偏工程就忽略数据口径，工程与数据在线上是同一件事。

## 面试追问

- 你的核心指标怎么定义？分母是什么？换一个口径结论会变吗？
- 数据清洗和标注你做了什么？标注一致性怎么保证？
- 你做过最接近 A/B 的实验是什么？如何排除其他解释？

## 输出格式

等级、数据链路证据、指标口径、实验设计、数据质量、缺口。

## 校准建议

数据/算法/量化岗 15%—28%；纯后端岗可降到 8%；产品岗 8%—12%。
