# 跨学科

> 维度技能 `talent-dimension-cross-discipline` · 版本 v1 · 本地存储 · 可回溯

## 考察目标

判断候选人是否带来团队现有体系之外、且可命名的学科能力；属于「补充能力」信号，不是人才质量分。

## 何时使用

团队需要补一个明确缺口（如控制、机械、数学、计算机）时使用；若该缺口已有人覆盖，把权重调低甚至设为 0。

## 判定方法

1. 先写下本岗位的核心学科集合。示例模板的核心集合是：稀土材料、冶金、化学/化工、物理。
2. 识别候选人的主学科与第二学科，不要只看毕业专业，也要看实际训练与产出。
3. 用一句话命名他带来的能力，例如「多智能体编排与评测」「第一性原理计算」「工业控制回路整定」，不能只写「跨学科」。
4. 判断该能力是否填补团队已命名的缺口；若没有缺口，判「否」并标注其核心方向。
5. 检查是否与技术栈、落地短板重复计分；同一证据只能支撑一个维度。

## 证据清单

- 学位/课程训练与项目中的实际方法。
- 能说明「团队现在做不了、他能做」的具体任务。
- 与核心方向的分工边界，而不是简单的专业名称差异。

## 分级标准

| 等级 | 分值 | 判定口径 |
|---|---|---|
| 是 | 1 | 存在明确、可命名的能力接口。 |
| 否 | 0 | 不存在该接口，或属于团队已有核心方向。 |

## 反偏差与反幻觉

这是最容易被「专业多样性」绑架的维度。参考案例中，跨学科权重过高会把结果系统性推向机械/控制专业。建议默认权重不超过 8%，并在偏差诊断中检查专业集中度。

## 面试追问

- 你的学科训练能解决我们哪个现有短板？请举一个我们团队目前做不了的具体任务。
- 这项能力和团队里已有的某个人如何分工？为什么还需要你？
- 如果只保留一项跨学科能力，你希望是哪一项？为什么？

## 输出格式

是/否、学科、具体能力、填补的缺口、与核心方向的重叠、置信度。

## 校准建议

若偏差诊断显示本维度入选者的机械/控制占比超过 60%，先下调权重，再复核判级是否把「专业不同」误当能力。

## 使用约束

本技能只服务于本地筛选与面试准备，不得把候选人姓名、联系方式、简历原文或任何可识别个人的信息写入交换包。判级必须引用证据；证据不足时降低置信度，不得编造。
