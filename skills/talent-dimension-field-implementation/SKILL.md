# 现场实施与客户界面

> 维度技能 `talent-dimension-field-implementation` · 版本 v1 · 本地存储 · 可回溯

## 考察目标

考察能否在客户现场把方案落地：部署调试、验收、培训、需求澄清与冲突处理，尤其适用于 2B、制造、医疗、能源项目。

## 何时使用

实施、交付、FAE、售前售后、驻场工程与解决方案岗位；纯研发岗可用作辅助。

## 判定方法

1. 看现场证据：部署环境、调试内容、验收标准、客户签字或上线记录。
2. 看问题处理：现场无法联网/设备不兼容/数据缺失时怎么绕过并交付。
3. 看客户界面：能否把需求翻译成范围与工作量，能否拒绝不合理要求。
4. 看培训与交接：客户或运维团队是否真的能接手。
5. 看风险意识：现场改动是否留回滚与记录，是否影响生产。

## 证据清单

- 驻场/实施项目清单与个人职责。
- 部署与调试记录、验收文档。
- 现场问题与临时方案（含回滚）。
- 培训材料、交接清单、客户反馈。

## 分级标准

| 等级 | 分值 | 判定口径 |
|---|---|---|
| 是 | 1 | 有可验证的一线/生产级证据，能说明个人负责范围。 |
| 部分 | 0.5 | 有中试、试点、内部工具或阶段性交付，尚未全面上线。 |
| 否 | 0 | 只有实验室、课程或他人主导的经历。 |

## 反偏差与反幻觉

不要用「能出差、能吃苦」替代实施能力；也不要因为岗位偏售前就默认技术弱。

## 面试追问

- 讲一次现场无法按方案执行的经历：约束是什么？你怎么绕过去？
- 验收标准是谁定的？你如何证明达标？
- 你在客户现场改过生产环境吗？改动前做了什么准备？

## 输出格式

等级、现场证据、问题处理、客户界面、交接与培训、缺口。

## 校准建议

实施/FAE/驻场岗 20%—28%；售前 15%；研发岗 5% 以内。

## 使用约束

本技能只服务于本地筛选与面试准备，不得把候选人姓名、联系方式、简历原文或任何可识别个人的信息写入交换包。判级必须引用证据；证据不足时降低置信度，不得编造。
